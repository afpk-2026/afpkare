# 부모가 없는 날 시뮬레이터 계산 명세

> 상태: v1.5 본문과 2026-11-09 「계산식 세부 과정」 PDF의 **보고서 재현 규칙**을 로컬 구현에 적용했다. 추가 제공된 `persona_v3.txt`는 v0.8 본문용 원본으로 핵심 경로를 대조했다. 기관 제도 해석은 독립 검증되지 않았다. 6절은 이전 배포의 가상 계약 기록, 7절은 새 계산 명세, 8절은 구현·검증 상태다.
> 기능 범위·화면·API·완료 기준: [frd.md](frd.md) · 미확정 질문과 후속 작업: [todo.md](todo.md)

## 1. 계산 원칙

- 계산은 FastAPI의 Python 함수 한곳에서 수행하고, 프론트엔드는 결과 표시와 서식만 담당한다.
- 금액은 API·계산에서 원 단위 정수로 다루며 연도·나이·2026년 실질 가격 기준을 명시한다. **현재 로컬 구현의 보고서 재현용 처리 순서와 끝수 규칙은 7절**에, 이전 가상 계산 계약은 6절에 둔다.
- 공적급여, 자녀 신탁 현금흐름, 부모 금융자산, 대안 비용을 분리한다. 연도별 제도 기준값은 별도 데이터로 둔다.
- 보고서의 1.30억·1.75억·1.81억 원은 대조값이지 식의 누락 부분을 역산하는 목표가 아니다. 수치가 다르면 반올림·연령 전환·명의별 재산·계산 순서를 확인해 기록한다.
- A/D의 비용·후회는 기준 사례의 보고서 고정값이다. 입력 변경에 따른 동적 계산이나 새로운 권고에 사용하지 않는다.

## 3. 보고서 식의 수학적 구조

다음은 v1.5 본문의 식이다. 시점·경계의 **보고서 엔진 재현 규칙은 세부 PDF를 옮긴 7절**을 따른다.

- **식 1 · 자녀 신탁:** `F[t+1] = (F[t] - 12 × w[t]) × (1 + r)`, `w[t] = min(max(0, N - Y[t] - B(F[t])), 월 인출 한도, F[t]/12)`.
- **식 2 · 최소 필요 잔액:** 56세 시작 잔액 후보를 바꾸며 대상 기간의 모든 해에서 `N - Y[t] - B(F[t]) - w[t] ≤ 0`을 만족하는 가장 작은 금액을 찾는다.
- **식 3 · 부모 금융자산:** `W[y+1] = W[y] × (1 + r) + L[y] + R[y] + P[y] + H[y] - C[y] - X[y] - M[y] - I[y] - K[y]`. 원본 `persona_v3.txt`는 신탁과 부모 금융자산에 동일한 `realReturn`을 사용한다. 기준 경로는 1%이며 화면의 수익률을 바꾸면 두 경로가 함께 바뀐다.
- **식 4 · 비용·후회:** `cost(a,s) = 3 × lifetime_shortfall(a,s) + lost_benefits(a,s)`; `regret(a,s) = cost(a,s) - min(cost(eligible_alternative,s))`. 전략별 최대 후회는 네 사건의 최대값이다. 반올림 전 값을 사용한다.

식 1의 월급여 판정 시점·인출 방식·기간 포함과 식 3의 연간 현금흐름은 세부 PDF 1·5·7장에서 **원 보고서 엔진의 가정**으로 설명한다. 로컬 구현은 그 가정을 적용하지만 기관 판정 규칙과 동일시하지 않는다. 남은 정책 판단은 [todo.md](todo.md)에서 추적한다.

## 4. 검증 기준과 입력 경계

- 대조 대상: 1.30억·1.75억·1.81억 원, 표 8 주요 행, 그림 6 경로, 표 9의 기준 사례 고정값. 보고서 표시 반올림값·원 단위 계산값·대표 연도 중간값을 나눠 대조한다.
- 경계: 64→65세, 급여 감액·중단점, 신탁 0원, 유족연금 0원, 재취업 0원, 수익률 0%, 생활비 185만 원, 종료 나이 83→95세.
- 방향: 생활비 증가가 필요 잔액을 감소시키지 않는지, 재취업 소득 감소가 부모 자산을 증가시키지 않는지 확인한다. 제도 비선형 구간의 예외는 해당 규칙을 조사한다.
- 금액 입력은 0 이상이며 유족연금·재취업 소득의 0원은 유효하다. 순실질수익률은 경제적으로 음수가 가능하므로 일괄 음수 거부하지 않고 수학적으로 `r > -1`을 요구한다. 제품 범위·정밀도는 팀 확정 전이다.
- 종료 나이는 부모 사망 시 지훈 씨 나이 56세보다 작을 수 없다. 상한·포함 연도는 미확정이다. NaN·무한대·잘못된 단위·지원하지 않는 필드·과도한 요청 크기는 서버에서 거부한다.
- 지훈 씨 명의 예금 1천만 원은 **이전 가상 계약에서는** 급여 재산에 포함했지만, 현재 로컬 보고서 재현식은 신탁 잔액 `F`만 넣는다. 이는 기관의 실제 자산조사에서 예금이 빠진다는 뜻이 아니다. 보수 차감 후 순실질수익률에서 미확인 상품 보수를 다시 빼지 않는다.
- 표 11의 `신탁 잔액 ÷ 1.19억`을 수급 자격 판정으로 사용하지 않는다. 자녀 총재산·소득을 반영하고, 기초연금 감액 시작 3.35억과 중단 4.40억을 구별한다.

## 6. 이전 배포 기록: 2026-11-09 구현용 가상 계산 계약 v1

사용자가 미확정 조건에 대한 판단을 위임하고 팀 보강 사항을 todo에 기록하도록 지시했다. 이에 `backend/app/assumptions.json`의 `scenario-2026-11-09-v1`을 **가정 기반 계산 계약**으로 구현했다. 위 1~5절의 보고서 원자료 공백이 기관 검증으로 해결된 것은 아니다. 보고서 원 엔진 복원·법적 수급 판정과 구별한다.

### 연간 처리·금액

- 2026년 자녀20세부터 적립, 2062년56세부터 인출. 종료 나이의 해도 포함한다. 65세는2071년에 바로 전환한다.
- 신탁은 연초 납입/사후 보충 → 연초 재산 급여 평가 → 연간 생활비 부족분 인출 → 연말 수익. 월 인출 한도150만 원은2026 실질 가격으로 유지한다.
- 자녀 예금1천만 원은 유지하고 수익/인출 없이 급여 재산에 포함한다. 부모 생전 급여는 소비에 쓰는 별도 흐름으로 신탁 적립에 더하지 않는다. API 적립기 `benefits:null`은 그 급여를 계산하지 않았다는 뜻이다.
- 원 단위 `Decimal` ROUND_HALF_UP. 급여는 월 소수 정밀도로 합산한 연간 합계만 반올림하며 인출 필요액은 연간 생활비−연간 유족연금−연간 급여다. API의 월 급여 구성값은 반올림 참고값으로 연간 총액과 최대 수 원 차이가 가능하다.
- 신탁은0 이하로 인출하지 않는다. 부족액은 별도로 누적한다. 부모 금융자산은 음수를 유지해 부족자금 규모를 나타내되 음수에 운용수익/이자를 붙이지 않는다.

### 공적급여 단순모형(기관 해석 미확인)

`A=연초 신탁+예금1천만`, `Y=월 유족연금`, `I=Y+max(0,A−2천만)×0.04/12`.

- 65세 전 장애인연금: `min(379700,max(0,1400000−I))`.
- 65세부터 기초연금: `min(349700,max(0,2470000−I))`, 부가급여: `min(50000,max(0,1400000−I))`.
- 저소득 입력의 생계급여: `max(0,820556−[Y+max(0,A−74000000)×0.0626+위 월 연금 합계])`.
- 이 연속 차액 모형에는 실제 급여별 절상·최소지급·조정·가구·재산군별 예외가 없다. 주거급여와 의료 현물급여는0원으로 수급을 판정한 것이 아니라 계산 범위에서 제외한다. 모든 가상 계산에 이 한계를 표시한다. 월 유족연금107만 원 기준 총금융재산1.19억에서 장애인연금0원이 되지만, 단일 문턱 비율을 법적 자격 판정으로 사용하지 않는다.

### 필요 잔액

`backend/app/engine.py:required`는 종료 해에서56세 방향으로 각 해의 최소 연초 잔액을 역으로 계산한다. 다음 해 필요 잔액과 당해 생활비를 충당하는 최소 원 단위 잔액을 이분탐색하고, 인출 한도를 검사한다. 이 모형에서 연간 필요 인출액의 자산에 대한 증가율은 최대0.7912이므로 `잔액−필요 인출액`은 비감소한다. 전체 기간의 인출 한도 포함 타당성이 전역 단조라는 가정은 사용하지 않는다. 마지막에 정방향 경로를 돌려 부족액0원을 확인한다. 한도 때문에 불가능하면 `null`과 `unsupported_withdrawal_cap`을 반환하고 거대한 숫자로 대체하지 않는다.

### 납입과 부모 현금흐름

- B:2026년5천만,2027~2031년600만,2031년 추가5천만. B′:2026년5천만,2031년5천만,2062년3,500만. 동일한 `contribution` 함수로 부모 차감과 자녀 유입을 맞춘다.
- 부모는 연초 잔액의1% 수익 후 연간 유입·유출을 반영한다. 신탁 수익률 변경 입력은 부모 수익률을 바꾸지 않는다.
- 근로 월520만2026~2030년; 퇴직급여2031년2억−세금379.5만; 재취업 입력값2032~2040년; 국민연금 월180만2036~2053년; 아버지2054년 사후 어머니 유족연금 월107만; 어머니2062년 사망 가정.
- 주택연금2039~2061년 월110만은 **가상 가정**이다. 집의 잔여 상속가액은 금융자산에 더하지 않는다.
- 부모 소비는 재직 월350만, 은퇴300만, 아버지 사후180만. 장애 추가비28.5만은 별도. 보험40만은2030년 종료, 대출91만은2035년 종료.
- B′ 사후 보충은 계획상 예정 재원으로 부모에서 차감한다. 부모가 음수인 경로는 실행 가능으로 표시하지 않는다. 보충 재원을 실제 상속으로 확보했다고 확정하지 않는다.

## 7. 새 「계산식 세부 과정」 PDF의 보고서 재현 규칙

2026-11-09 제공된 46쪽 「계산식 세부 과정 (본문 v1.5 기준)」은 보고서 엔진의 상수, 처리 순서, 절사 규칙, 중간값을 상세히 제공한다. 사용자 선택에 따라 로컬 계산 코드를 이 규칙으로 교체했다. 이어 제공된 `persona_v3.txt`는 스스로 **v0.8 본문용**이라고 밝힌다. 이 파일을 직접 실행한 `--check` 결과는 41개 중 39개 일치·2개 불일치로 PDF 설명과 같았다. 원본이 언급한 TypeScript 엔진은 별도 파일이 없어 직접 대조하지 않았다. 아래 수치는 **PDF 및 v0.8 원본의 기대값**으로 표기한다.

### 7.1 시간축·단위·끝수·탐색 (PDF 1장)

- 2026년 실질 가격을 고정하고 기준 제도값도 민감도 외에는 2026년 값으로 유지한다. 평생 금액은 월액×12를 매년 할인 없이 합산한다. 2026년 지훈 씨 20세, 2062년 56세, 2071년 65세다. 56~83세는 **양 끝 포함 28개 연도**이고 장수 비교는 95세 해를 포함한다.
- 사망 시점은 PDF가 인용한 2024 생명표와 `round_half_even`으로 아버지 2054년, 어머니 2062년으로 둔다. 다른 페르소나의 .5 경계에서 JavaScript `Math.round`로 대체하면 달라질 수 있다.
- 원 엔진은 비율을 100만 배 정수로 만들어 곱·나눗셈하고 정수 몫을 쓴다. 신탁·부모 잔액 갱신은 `trunc`(0 방향 절사), 월 인출 가능 잔액은 `floor(F/12)`, 세액은 별도 `floor`를 적용한다. 부모 잔액이 음수일 때 `floor`와 `trunc`를 혼용하지 않는다.
- 식 2의 원 엔진 `min_trust`는 **0~15억 원을 500만 원씩 순차 탐색**해 부족한 해가 0인 첫 잔액을 고른다. 급여가 자산에 따라 계단식으로 변하므로 임의 잔액의 전 기간 타당성을 단조라고 가정해 이분탐색하지 않는다. 수급 문턱 탐색 `edge`만 0~10억 원 원 단위 이분탐색이다. 해답이 없으면 `None`이다.

### 7.2 공적급여 함수 (PDF 4장)

- 보고서 엔진은 `F=해 초 신탁 잔액`으로 급여를 평가한다. 기초생활 소득인정액은 `I기 = Y + G + max(0,F−5,000,000−80,000,000)×0.0626`, 장애인연금·기초연금 소득인정액은 `I장 = Y + floor(max(0,F−20,000,000)×0.04/12)`다. `Y`는 월 유족연금, `G`는 65세 이후 기초연금이다. 기초생활에는 기초연금은 넣고 장애인연금은 넣지 않는다는 PDF의 **엔진 가정**을 그대로 표시한다. 지훈 씨의 다른 소득·재산·부채가 없는 1인 가구 모형이다.
- 18~64세 장애인연금은 `I장≤1,400,000`일 때 기초급여 최대 349,700원, 소득역전 감액 20,000원 단위 올림(최소 20,000원), 부가급여 90,000/80,000/30,000원 구간을 적용한다. 유족연금 107만 원이면 부모 사후 신탁 잔액 0원에서 월 420,000원, 119,000,300원부터 0원이라는 **PDF 기대값**이다. 차상위 구간 전환은 88,388,499원이다.
- 65세부터 기초급여 대신 기초연금 최대 349,700원(감액 시 10원 미만 버림·최소 34,970원)과 장애인연금 부가급여를 따로 계산한다. 유족연금 107만 원이면 신탁 잔액 0원에서 월 399,700원, 1.19억 원을 넘으면 부가급여 50,000원이 끊긴다. 기초연금의 감액 시작은 약 3.35억 원, 수급 중단은 약 4.40억 원이다.
- 생계·의료·차상위 기준은 PDF에서 각각 월 820,556/1,025,695/1,282,119원이다. 유족연금 107만 원인 기준 사례에서 생계·의료는 0원이나, 유족연금 변경 입력에서는 판정이 달라질 수 있다. 주거급여 민감도는 PDF 4.7장의 **원 엔진 밖 보조 계산**이며 그룹홈 임차료 인정도 미확인이다.
- 위 규칙은 PDF가 보고서 엔진의 재현법으로 제시한 것이며 **기관의 실제 수급 자격을 검증한 코드북이 아니다.** 현재 로컬 구현은 PDF와 같이 다른 금융재산인 지훈 씨 예금 1천만 원을 함수에 더하지 않는다. 실제 수급 판정의 자산 반영 여부는 별도로 확인해야 한다.

### 7.3 자녀 신탁과 검증용 중간값 (PDF 5·6장)
